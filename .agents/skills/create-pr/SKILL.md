# Pull Request 생성

사용자가 GitHub Pull Request 생성을 요청할 때 사용한다. 공유 대상에 따라 PR 본문 언어를 선택한다. 외부 공유에는 영문, 내부 공유에는 한글을 사용한다.

## 위임 경계

**PR 생성 워크플로는 서브에이전트만 실행할 수 있다.** 메인 에이전트에서 이 스킬이 호출되면 작업을 서브에이전트에 위임하고, 메인 에이전트는 직접 PR 생성 명령을 실행하지 않는다. 메인 에이전트는 작업이 끝난 뒤 서브에이전트의 결과만 보고할 수 있다.

서브에이전트는 사용자가 명시적으로 승인한 경우에만 PR을 생성하거나 갱신할 수 있다. 위임을 사용할 수 없으면 작업을 중단하고, 메인 에이전트에서는 PR을 생성할 수 없다고 사용자에게 알린다.

## 서브에이전트 워크플로

1. 저장소 상태, 현재 브랜치, 원격 저장소, 기존 Pull Request를 확인한다. 관련 없는 변경사항을 삭제하거나 되돌리지 않는다.
2. 저장소 설정 또는 사용자 지시에서 대상 브랜치를 확인한다. 소스 브랜치가 준비됐는지 확인하고, 승인된 PR 생성에 필요할 때만 푸시한다.
3. 공유 대상을 선택한다.
   - 외부 또는 공개 대상이면 [외부 공유용 템플릿](references/external/pr-template.md)만 읽는다.
   - 내부 대상이면 [내부 공유용 템플릿](references/internal/pr-template.md)만 읽는다.
   - 공유 대상이 명시되지 않았으면 저장소 공개 상태로 판단하고, 여전히 모호할 때만 사용자에게 질문한다.
4. 실제 diff, 커밋, 검증 결과를 바탕으로 간결한 PR 제목을 작성하고 선택한 템플릿의 본문을 채운다. 참조 템플릿은 수정하지 않는다.
5. Pull Request를 생성하고 URL, 대상 브랜치, 소스 브랜치, 실행한 테스트를 반환한다. 생성에 실패하면 오류를 보고하고 브랜치는 그대로 둔다.

두 템플릿을 함께 읽지 않는다. 각각 해당 공유 대상에서만 필요한 조건부 지침이다.
